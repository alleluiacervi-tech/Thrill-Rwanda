# Payment security and access

- Keep API keys, callback passwords, independent JWT signing secrets and cron authorization server-side. Separate testing and production credentials and data. Rotate compromised or obsolete credentials and confirm old attempts can still be verified before cutting over merchant accounts.
- Booking invoices require signed-in ownership and accepted terms. Guest links have 256-bit random tokens, digests at rest, expiry and revocation. Treat a shared link as access to the commercial invoice. The pay paths send no-store and no-referrer headers. Review edge, application, analytics and access logs for URL-redaction and retention before launch.
- Payment methods and amounts are computed on the server. A submitted amount only confirms the displayed invoice amount; it never controls a charge. Invoice reservations use database locks, an active-attempt unique index and stable merchant UUIDs before outbound calls. Local timeout or a missing provider record leaves the balance blocked for review.
- Webhook login checks the configured username/password using constant-time digest comparison. Signed tokens are audience-bound and expire. Callback bodies are size-limited and authenticated. Durable de-duplicated event records store normalized results only. Raw card data, PINs and provider payloads are kept out of the database.
- Wallet authorization stays in the customer wallet. Card entry and any supported challenge stay on UrubutoPay. The hosted link is accepted only from the configured provider origin and checkout path. Provider status is independently fetched and matched to currency, amount, merchant, service, channel and reference. Checkout does not offer automatic provider fallback.
- Finance and admins verify settlement against an approved account and references. Admin routing requires administrator access and the existing two-factor guard. Supplier approval, refunds and disbursement have separate authority. On a mismatch, preserve the attempts and evidence before any corrective action.
- Before activating live processing, review hosting and vendor agreements for Vercel and Neon, any overseas storage or transfer authorizations, credential rotation, alerting and the applicable PCI scope with the merchant/acquirer. The DPO describes authorization for overseas storage and separate data transfer conditions.
